## Browser GIS throughout the Atlas

Use the [browser GIS guide in the Book](https://jltobias.github.io/JupyterLite-Learning-Atlas/book/browser-gis.html) or [the same guide in Lab](https://jltobias.github.io/JupyterLite-Learning-Atlas/lite/lab/index.html?path=browser-gis.ipynb), then run the [GIS export/review workbench](https://jltobias.github.io/JupyterLite-Learning-Atlas/lite/lab/index.html?path=gis-workbench.ipynb). Each of the **46 project chapters and 46 source-course guides** offers a subject-specific question, a RustGIS task, a GeoLibre task, an optional assistant prompt, a separate GeoAI extension and a human evidence check. The 796 imported source lessons retain their original code and their course-guide handoffs; they are not all rewritten or universally browser-certified.

The practical connection is **notebook → attributed GeoJSON → import into a browser GIS → inspect the map/table/tool results → revise and document**. Open [RustGIS Web](https://web.rustgis.app/) or [GeoLibre Web](https://web.geolibre.app/) and use its file picker to load the exported file. The apps have separate projects and storage. The workbench uses real Fresno Census tracts for a clearly identified common practice example, or an explicitly chosen attributed WGS84 GeoJSON file. Other real inputs are available through the [Map and Scene Atlas](https://jltobias.github.io/JupyterLite-Learning-Atlas/teach/) and existing source lessons. A common practice layer does not become a cholera, coral, mobility or other subject observation by changing the chapter name.

The workbench also supplies optional CSV preparation and returned-artifact inspection recipes. Preparation keeps original columns, explicit geographic coordinate/ID mappings, typed derivatives, source hashes and the retained dataset notices. App-returned files are inspected separately against original portable IDs and values; they are not silently treated as fresh Census inputs or stripped of provenance.

The chapter activities connect spatial questions to uncertainty, users' decisions and small Design Thinking/Human-Centered Design iterations. GIS styling, AI-assisted operations and fitted GeoAI models have different evidentiary requirements. Existing GeoLibre–RustGIS, Population export and OneHealth join lessons remain linked with their own data status and runtime boundaries. Missing or controlled inputs stay explicit continuations.

**Optional AI assistants and Ollama.** Follow the official [GeoLibre assistant guide](https://geolibre.app/user-guide/ai-assistant/) and [RustGIS assistant guide](https://rustgis.app/user-guide/assistant/). Ollama needs a separately installed/running server and an installed model able to use the assistant's tools. Allow the exact origin of the selected GIS web app; CORS settings and browser local-network permission are separate. The Book explains provider base URLs and user-run setup, with no model calls, installations, service configuration, credentials or uploads performed by the Atlas. A localhost endpoint can route to a cloud-backed model; local-only inference requires an actually local model and appropriate settings. Hosted providers can receive relevant tool results/feature values. Check the tool transcript, identifiers, counts, CRS and units, and reproduce a small result before accepting the map or model's interpretation.
